# 代码规范（通用）

> 适用：Node/TypeScript 工程。示例是通用示意，不是任何具体项目的路径；
> 本项目的偏差见同目录《项目特定规范.md》。

## 1. 文件与目录

| 类别 | 规则 | 示例 |
| --- | --- | --- |
| 模块目录 | 小写语义名，一个模块一个目录 | `parser/`、`renderer/` |
| 模块内文件 | 小写语义名，单文件一职责 | `index.ts`、`writer.ts` |
| 契约与类型 | 集中成小写语义名文件，不与实现混放 | `contracts/a.ts`、`contracts/b.ts` |
| 测试 | 不入库，本机放 `localscripts/tests/<包名>/`，文件名 `<套件名>.test.ts` | `localscripts/tests/core/tree.test.ts` |
| 脚本 | 入库的放 `scripts/`；本机脚本放 `localscripts/` | `scripts/ensure-libs.cjs` |

每个对外模块给一个 `index.ts` 门面，包内私有模块不经门面暴露。

## 2. TypeScript 标识符

- 接口与类型：PascalCase，`CreateOptions`、`SnapshotResult`；类型名即文档，不加 `I` 前缀；
- 函数：camelCase 动词开头，`jsonToDiagram`、`defaultNode`；
- 常量：UPPER_SNAKE，放模块顶部；外部可调参数走 options 或入参，不散落魔数；
- 布尔：语义化形态，`ok`、`isOpen`、`hasParent`，不写 `flag`、`status2`；
- 禁止 `any`；禁止未使用的 import 与变量。

`tsconfig` 至少开 `strict`、`noUncheckedIndexedAccess`、`noUnusedLocals`、
`noUnusedParameters`；数组与 Map 取值显式判空，不靠 `!` 蒙混过关。

## 3. 注释与文案

- 文件头注释写清职责与"为什么"；
- 关键机制必须留注释：数字格式化规则、单位与缓存语义、以及"顺序即协议"的地方；
- 注释用中文，标识符用英文；
- 用户可见的错误消息用中文；内部消息可保留英文短语加 `[phase]` 前缀，
  便于与外部规范或原始实现对照；
- 注释解释为什么这么做，不复述代码在做什么。

## 4. 确定性与失败分界

- **类型即契约**：跨模块流转全走显式类型，禁止隐式 any 通道；
- **顺序即协议**：产物里的元素顺序、字段顺序、条目顺序是协议的一部分，
  非必要不改；要改就当行为变更对待；
- **常量不优化**：布局常量、缓存魔数、哈希规则一改就产物漂移，
  照抄的常量保持照抄；
- **失败分界**：求值失败或资源缺失走软失败，比如不做修改或者保留原件；
  输入校验与契约错误走硬失败，直接抛错中止，不静默降级；
- **每轮门槛**：`typecheck` 与控制台测试全绿，才允许提交。

## 5. 验证脚本

验证只对着**外部事实**：产物文件与包内 XML、Word 回读结果、对外契约、库的落盘内容。
断言不许落在被测实现自己产出的东西上。下面几类一律不写，发现即删，不做修补：

- 断言界面自己渲染出来的文字，改一处文案就得改一片断言，证明不了行为；
- 把界面 DOM 或对象全量 dump 出来再比字符串；
- 期望值由被测实现自己算出来，再拿它比对；
- 只证明"没崩"的弱断言，能恒真、无法反证；
- 逐字比对文案的所谓对照测试，对照键要落在规则与产物上。

新写一个验证脚本之前先回答一句：它证明的是哪条外部事实。答不上来就不写。
历史遗留的同类脚本直接删除，不修补也不保留。
