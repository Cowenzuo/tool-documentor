# 文档规范（通用）

> 适用：中文技术文档的正文，研究分析、架构说明、使用指南、README 都算。
> 写法面向 GJB 438C 类技术文档的行文习惯，并按代码仓库文档的特点补了适用边界。
> 代码注释与提交消息不归本文管，见同目录《代码规范》《提交规范》。

## 1. 总原则

正文写给人看，不是写给机器看。技术细节要准确，节奏要像讲解而不是罗列。
每段先说结论再说细节，结论放段首。

## 2. 句子结构

### 2.1 一句话只讲一件事

```
❌ 系统监测采用轮询与事件推送混合模式采集数据，常规状态指标包括 CPU 使用率、内存占用、网络流量和接口响应时间，每 5 秒轮询采集一次。
✅ 系统监测这边，仪表盘上放着几块仪表和趋势图，分别对应各服务器的 CPU、内存、网络使用率，还有各算法模块的运行状态。
```

### 2.2 先说结论再说细节

```
❌ 格式校验基于 JSON Schema，系统初始化时加载各接口的 Schema 定义文件，入站请求的 JSON 正文逐一与对应 Schema 匹配。
✅ 格式校验用 JSON Schema 来做。系统启动的时候把每个接口的 Schema 文件加载进来，来了请求就把 JSON 正文和对应的 Schema 对一下。
```

### 2.3 用逗号和句号控制节奏

短句为主，允许偶尔长句。一段 3 到 5 句，超过 8 句就拆开。

## 3. 用词禁忌

### 3.1 禁止的写法

| 禁止 | 原因 | 替代 |
| --- | --- | --- |
| （括号夹注） | 打断阅读流 | 拆成独立短句 |
| ——破折号—— | 学术腔 | 逗号或句号 |
| 本项通过……实现 | 机械翻译腔 | 直接说怎么做 |
| 基于……的…… | 啰嗦 | 动词开头直说 |
| 对其进行…… | 指代不明 | 说出具体名词 |
| 面向人的、通俗版、大白话等自我标榜 | 像免责声明，正文质量不靠标签 | 删掉 |

### 3.2 保留的结构标记

括号和破折号在正文散文里禁用。下面几类不是散文，可以保留：

- 列表序号 `(1)(2)`，属结构标记；
- 代码块、目录树、XML 片段内的注释，如目录树里的
  `（类型登记表，第 2 章）`，起定位作用；
- 表格单元格内的短注，表格是结构不是句子；
- 取证符号 🔍 📚 ❓。

## 4. 段落组织

### 4.1 每段一个主题

```
✅ 用户管理这边，管理员可以新建、编辑、禁用和删除账号，账号列表支持按角色筛选，也可以直接搜关键词。新建用户时顺手分配一个角色，角色的权限决定了这个用户登录后能看到哪些菜单、能点哪些按钮。

角色管理用一棵权限树来配置，管理员勾上或取消某个权限项就立刻生效，不用重启。
```

### 4.2 段落之间要有逻辑承接

后一段接前一段的话头往下说，不另起炉灶。前一段说连接断了会自动重连，
后一段顺势讲重连间隔越来越长，而不是跳到别的话题。

## 5. 技术细节的处理

### 5.1 数字融入句子而非罗列

```
❌ 路由转发延迟不超过 50ms，格式校验在 100ms 内完成。
✅ 整个校验过程控制在 100 毫秒以内，用户基本无感。路由判定不拖沓，50 毫秒以内完成。
```

### 5.2 技术名词配解释

名词第一次出现给一句白话定位，别默认读者都懂。

```
❌ 样式索引只有文档内有效，index 3 表示 Normal。
✅ 样式索引 3 表示 Normal。这个数字不是全局标准，只在这份文档里有效；
   换一份文档，Normal 对应的索引可能是别的数字。
```

### 5.3 为什么 > 是什么

不只说做了什么，顺手点一下为什么这么做。

```
❌ 封面图存成 EMF，放在 docProps 目录下。
✅ 封面图存成 EMF，放在 docProps 目录下。EMF 是矢量图格式，放大预览不糊，
   所以 Visio 存了这张封面。解析图纸内容用不上它，讲属性时一笔带过即可。
```

## 6. 口语化程度控制

### 6.1 可以用

"这边""顺手""飙红""打回去""不拖沓""省了不少事""挡在身后""进门第一道关口"

### 6.2 不能用

"搞定""OK""牛逼""一大堆"。太随意，正式文档不允许。

### 6.3 度

每段 1 到 2 个口语化表达，多了显得轻浮。技术分析段偏严谨，
综述总览段可以放松。

## 7. 自检清单

写完逐段过一遍：

- [ ] 有没有括号夹注？有就拆成句子；
- [ ] 有没有破折号？有就改成逗号或句号；
- [ ] 有没有"通过……实现"这类腔调？有就直说怎么做；
- [ ] 每句话是不是只讲了一件事？
- [ ] 数字是融在句子里还是干巴巴罗列？
- [ ] 每个技术名词有没有顺手解释为什么？
- [ ] 段落之间有没有逻辑承接？
- [ ] 有没有自称"面向人""通俗版"？有就删；
- [ ] 整段读起来像不像人在说话？

## 8. 适用范围与例外

- 适用：仓库 `docs/` 下阅读型文档的正文，以及新写的同类文档；
- 不适用：历史快照材料不回溯改写，要更正就在新文档里说明；
- 不管结构：章节怎么排、分几节属于结构体例，由各文档区的体例文档规定；
- 不管代码与提交：注释、命名、提交消息见同目录《代码规范》《提交规范》。
