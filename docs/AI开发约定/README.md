# AI 开发约定

> 本目录回答"活该怎么干"：怎么写提交、怎么写代码、怎么写文档，以及本项目
> 特有的约定。分两类：**通用规范**三篇，换任何 Node/TS 工程都成立；
> **项目特定规范**一篇，只在 tool-rwdoc 成立。
>
> 归属判断很简单：条文里出现本项目的路径、脚本名或验收数字，就写进项目篇。

| 文档 | 类别 | 内容 |
| --- | --- | --- |
| [提交规范.md](提交规范.md) | 通用 | 提交消息格式、工作流习惯、版本管理 |
| [代码规范.md](代码规范.md) | 通用 | 目录与文件命名、TS 标识符、注释与文案、确定性与失败分界 |
| [文档规范.md](文档规范.md) | 通用 | 中文技术文档的行文约束与自检清单 |
| [项目特定规范.md](项目特定规范.md) | 项目 | 支持范围、仓库结构、构建与运行、产物命名、验收口径、技术红线、文档地图 |

本项目与通用篇的偏差集中在项目篇第 3 节：脚本用 `*.cjs`，类型检查的实际开关，
以及内部日志的模块前缀。

相关文档：WORD 包结构与本工程的写入方式见 `docs/WORD解压结构研究/`；
Word 实测核对与踩坑记录见 `docs/WORD处理经验/`。
