# PLAN-14 老工程打开与模板引用迁移

> 状态：已实施。范围是 PLAN-12 把模板引用换成 uuid 之后，用户手上那批老工程还能不能打开。
> 本文接 PLAN-12 第 6 节：那一节只把模板库迁到 uuid，没管工程侧的引用怎么写。

## 1 现象与原因

- 现象：老工程点开就失败，界面只回一句「操作失败」，看不出是哪一步不行。
- 原因：老工程的模板引用是按名字写的。锚点里是 `template`，库表里是 `project.template_name`；
  PLAN-12 之后打开工程要读 `template_uuid`，而老库里没有这一列，
  `SELECT name, template_uuid FROM project` 直接抛 `no such column: template_uuid`，
  工程连树都读不到。六份在用工程全是这个写法，也就是一份都打不开。
- 界面那一句「操作失败」是第二个问题：主进程抛回来的话本来就是给人看的中文结论，
  被统一替换掉之后，出问题连一句能拿来定位的话都没有。

## 2 口径

| # | 件 | 定 |
| --- | --- | --- |
| 1 | 读库 | 按 `project` 表实际存在的列读：有 uuid 用 uuid，只有名字用名字，都没有就是空引用 |
| 2 | 老名的形态 | 旧版本模板 JSON 里只有一个 `name` 字段，写法是「中文名(英文名)」，例如 `438C-软件设计说明(SDD)` |
| 3 | 认引用的范围 | 只在"库里没有 uuid"时按名字认一次；认三种写法：中文名、英文名、「中文名(英文名)」 |
| 4 | 只认唯一一份 | 认不出、或两份模板同名，一律按悬挂处理，交给用户重选，不猜是哪一份 |
| 5 | 写回时机 | 打开工程不写盘；第一次保存时把 uuid 写进库表与锚点，老库同时补列 |
| 6 | 迁移边界 | 只补 `template_uuid`，`template_name` 原样留着；没认出 uuid 的工程把名字留在锚点里，下次还能再认 |
| 7 | 失败的说法 | 打开、保存与编辑失败一律把主进程给的那句话显示出来，不再统一写「操作失败」 |
| 8 | 悬挂的样子 | 认不到模板时工程照常打开、照常编辑；状态栏写「模板未认到」，打开时提示「模板未认到：<旧名>」 |

名字仍然不参与匹配：这一条只在老工程上读一次，认到就换成 uuid 记，新写入的数据里不出现模板名。

## 3 落点

| 文件 | 改动 |
| --- | --- |
| `core/anchor.ts` | 读 `template` 存成 `legacyTemplateName`；写的时候认到 uuid 就只写 `template_uuid`，没认到就把名字写回 `template` |
| `core/store.ts` | `project` 表按列名读取；新增 `legacyTemplateName()`、`setTemplateUuid()`；保存时补 `template_uuid` 列并写 uuid |
| `templates/identity.ts` | `legacyNameOf` 拼老写法，`normalizeTemplateName` 全角转半角、去空白、不分大小写 |
| `templates/resolve.ts` | `findStructureByLegacyName`：唯一命中才算认到 |
| `templates/manager.ts` | 名字认引用落到已加载的注册表上，读不出来的那份不算 |
| `project-service.ts` | 打开时走 `resolveTemplateRef`；`projectInfo` 带出 `legacyTemplateName` |
| 渲染层 | 状态栏认不到时写「模板未认到」；打开时提示旧名；失败提示改带原因 |

## 4 自检

| 命令 | 覆盖 |
| --- | --- |
| `pnpm check:open` | 服务侧，拿一份真实老工程跑：1038 章节、1432 内容块，验打开、认引用、块零跳过、保存补列、再打开、悬挂、撞名、名字的四种写法 |
| `pnpm check:open:ui` | 界面侧，起真实 Electron：夹具摆一份老格式工程，点「最近打开」进工程、看状态栏、物理点保存、读回库与锚点、退出再打开 |

## 5 不做

- 不做「重选结构模板」的界面入口：认不到时工程仍可打开、可编辑，导出是另一件事，另立方案；
- 不回填老库里的历史列，`node_type` 之类的字段本就读不读都行；
- 不把模板名写进任何新工程的数据。

## 6 验收

1. 在用的老工程全部能打开，模板名认得出来，内容块零跳过；
2. 保存一次之后：库里补上 `template_uuid`、锚点换成 uuid、`template_name` 与原有数据不变；
3. 模板改名或删掉之后，工程仍能打开，只是显示「模板未认到」；
4. 新建工程与已迁移的工程走的是同一条 uuid 路径，锚点里不出现 `template`；
5. 导出照常：老工程迁移后能出 DOCX，段落数与内容块数对得上。
