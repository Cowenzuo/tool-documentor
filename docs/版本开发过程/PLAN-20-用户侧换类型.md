# PLAN-20 用户侧换类型

> 状态：口径待拍板。本文先把问题列清楚，取舍定了再动手。
> 范围是 PLAN-16 第 5 节"还留着没做的"第一行：**用户侧换类型的入口**。

## 1 这一轮要解决的事

PLAN-16 第 5 节当初把它留下，理由写得很清楚：

> 换类型要定"内容怎么搬"（文本转列表？表转文本？），那是新功能的取舍，不是取交的事。
> 排版开着时"删一块再加一块"就是同一件事，写入侧已按矩阵放行。

所以这一轮真正要回答的是一个产品问题：**换过去之后，旧内容去哪**。
权限那一半（编辑 × 排版 × 块档位）不用重新定，PLAN-13 第 1.3 节与 PLAN-16 第 2 节的矩阵已经写死，
写入侧也照着它拦了。

## 2 现状

| 层 | 现状 |
| --- | --- |
| 写入侧 | **已经放行**。`project-service.updateBlock` 比对 `existing.type !== input.block.type`，允许的条件是 `排版开着 && 块上没有锁`，拒绝语取 `reshapeRefusal`，落库时整块替换且 `lock` 按原块保留 |
| 自检 | `pnpm check:locks` 已覆盖：keep 块换类型被拒（"类型不能改"）、自由块换类型放行 |
| 界面 | **没有入口**。`BlockCard.tsx` 第 69 行的注释就写着"块类型在这套编辑器里没有切换控件" |
| 模板侧 | 有先例但是另一回事：`BlockForm` 的类型下拉只改 `type` 一个键，其余键原样留着，靠校验收拾。工程侧是结构化编辑器，照搬不了 |
| 写入命令 | 工程工作区的 `apply-project.cjs` 有 `set-node-block`（整块替换，日志里就写"第 N 块 text → table"），但没有按内容搬运的换类型命令：换过去的内容要手工写全 |

今天用户想换类型，只能"删掉这一块 + 加一块新的"，**旧内容全丢**；
连"有序列表改无序列表"这种本该无损的一次也要重打一遍。

## 3 要定的取舍：内容怎么搬

八种类型的"装内容的地方"各不相同：

| 类型 | 主文本落在哪 | 形状类字段 | 题注 |
| --- | --- | --- | --- |
| 文本 | `content`（多行） | — | — |
| 有序／无序列表 | `items[]`（每项一行） | — | — |
| 代码 | `code`（多行） | `language` | — |
| 公式 | `latexCode`（单行） | — | — |
| 流程图 | `code`（多行） | — | `caption` |
| 表格 | `headers` + `data[][]`（二维） | `cols`／`rows`／`rowSpans`／`mergeVertical` | `caption` |
| 图片 | 没有文本 | `imagePath` | `caption` |

三种可选口径：

- **甲：一律取新类型的空块**。最简单，语义最干净，但"有序改无序"也清空，最常做的一件事反而丢内容；
- **乙：全互通 + 主文本映射**（建议）。按下面那张表搬，装不下的部分丢掉并让用户知道；
- **丙：只放开同形的**（列表互换、文本↔列表）。改动最小，但"表转文本"这类真实需求还是得删了重加。

### 3.1 建议的搬运表（口径乙）

1. 文本 ↔ 有序／无序列表：按行拆项、按行拼回，空行丢掉；
2. 文本 ↔ 代码 ↔ 公式 ↔ 流程图：整段搬进对方的主文本位；代码的 `language`、流程图的 `caption` 不跟着走；
3. 表格 → 文本：一行一行拼，一格一格用制表符隔开，表头当第一行；表格 → 列表：每行一项；
4. 文本 → 表格：一行一行拆，**一列 N 行**（不猜分隔符），表头留空；这样 3 与 4 往返不丢字；
5. → 图片：得到一张还没选文件的图片块（现状"未选择图片"就是它）；图片 → 文本：题注有字就搬进文本，没有就空；
6. 题注、表格形状（列数／表头／纵向合并）、图片文件引用：**换出去就丢**，这是"换类型"这三个字的定义；
7. 块档位 `lock` 跟着原块保留（写入侧已经这么做了，界面这一侧不改）。

### 3.2 要不要确认

产品里已有先例：表格缩表会弹一行内联确认（"这次缩减会丢失 N 行 M 列（共 K 个非空单元格）"），
不静默截断。换类型建议照这个来，但只在真的会丢东西时问：

- 会丢：表格出、图片出、其它类型进图片（`imagePath` 或二维数据装不下）；
- 不丢：文本 ↔ 列表、代码／公式／流程图之间的互搬。

## 4 机制上的坑（动手时必须一条条处理）

1. **防抖队列会把类型改动静默回滚**：`NodePage` 每个下标有 600ms 的挂起编辑（`pendingRef`），
   定时器到点会把**旧类型**的那份块写回去。加块、删块、移动三处都先 `await flushPending()`，
   换类型必须走同一条路；
2. **失败时界面与库会不一致**：`handleChange` 先改本地 `blocks` 再发请求，失败只弹 toast，
   界面上还是新类型，下一次对账才把旧类型拉回来。换类型比改一个字段显眼得多，这条得处理干净
   （要么失败回滚本地态，要么不做乐观更新）；
3. **撤销的步名与合并**：现在 `updateBlock` 走 `withSnapshot('修改内容', …, 'block:update:<节点>:<下标>')`，
   换类型与随后的内容编辑会被合并成一步，历史面板上还叫"修改内容"。建议换类型单独一步、不合并；
4. **置灰理由必须与写入侧同一句**：用 `reshapeRefusal`，不要另写一套说法（文案即契约，
   `pnpm check:terms` 看住的就是这一条）；
5. **换进表格要自带合法形状**：`updateBlock` 会跑 `assertTableShape`，而 `cols <= 0` 是硬拦
   （`createBlock('table')` 给的是 `cols: 0`）。注意**加块那条路不校验**，两条路现在的宽严不一致；
6. **卡片的重挂载与局部状态**：`blockKeys` 按块对象配键，换类型不改长度，卡片不会重挂载，
   旧编辑器里的局部状态（图片上传忙碌态、表格焦点、折叠态）不能串到新编辑器上；
7. **折叠摘要是按类型算的**：换完之后卡片头上的摘要、徽标、档位标记都要按新类型重画；
8. **列表编号会跟着变**：导出侧按块分编号组（`writer.ts` 的编号克隆），列表换出／换进都会改变编号输出。
   属预期，但要在文档里说清，别当成缺陷；
9. **图片会变孤儿**：图片块换出去之后，`images/` 里那个文件不再被引用，现在没有清理机制。
   建议这一轮不做清理，只把"不清理"写明；
10. **列表子标题章节**：`isSubTitle` 只影响标题渲染与编号层级，不限定块类型（已核对），
    所以不必特判；但要在自检里覆盖一次"列表子标题章节里把列表换成文本"；
11. **老档位 `type` 与坏数据**：`lock: 'type'`（旧档位）与 keep／readonly 一样不许换，写入侧已按
    "有锁就不换"处理；类型认不出来的块在载入时就被拦下了，界面到不了这一步。

## 5 落点与自检

| 件 | 落点 |
| --- | --- |
| 搬运规则 | 建议放 `packages/core`（纯数据、无界面依赖），这样工程工作区的写入命令以后能复用同一份，与 `table-limits.ts` 同一个理由；复用点就是那份 `set-node-block` 之前先按规则搬一次 |
| 词 | 动作词进 `packages/desktop/src/shared/permissionTerms.ts`，界面上第二套说法一律不要 |
| 入口 | `BlockCard` 卡片头（类型徽标＋名字那一处），菜单项复用 `BLOCK_TYPE_LABELS` 与 `describeBlockType`，与"添加内容"菜单同一套词 |
| 自检 | `check:locks` 补搬运结果与拦放；`check:terms` 补词表与置灰理由同源；`check:terms:ui` 补界面：排版关／keep／readonly 三种情况入口灰着且理由同一句，自由块换完类型落库干净、锁没被洗掉、能撤销 |

## 7 顺带发现（不属本文范围）

表格缩表那行确认写着"无法撤销"，但缩表走的是 `updateBlock`，
`withSnapshot` 在改之前存了整块快照，撤销栈里那一步的 `before` 就是缩表前的完整表格；
合并键只影响"与相邻一步合不合并"，不影响能不能撤。**这句话很可能是错的**，需要实机验一次：
若确实能撤销，那是一句要改的文案（另开分支）。
