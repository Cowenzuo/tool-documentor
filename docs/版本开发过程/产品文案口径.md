# 产品文案口径约定

> 适用范围：**所有用户可见文本**——界面按钮/占位/工具提示、向导与导出对话框、Toast 提示、
> 模板 JSON 的 name/description 字段、导出结果 warnings、错误提示。
> 这些规则来自一次评审：把实现机制（Visio 对象/转换/嵌入/预览/占位/槽位/注册表/兜底）
> 与外部文件名（template.docx）写进用户文案之后，用户看到的就成了不该他知道的东西。
> 留着这几条是为了防止回归。

## 规则

1. **说人话**：一句话说明"对用户意味着什么"，不解释"怎么实现的"。
   - ✗ "Mermaid 图块自动转换并嵌入为可编辑 Visio 对象（双击编辑）；预览图在机器具备能力时自动附加……"
   - ✓ "导出时将一并嵌入 N 张图。"
2. **不出现文件/格式/工具名**：用户不该知道也不持有这些来源（template.docx、uuid、stylemap、VSDX、Mermaid、LaTeX 仅术语需软化）。
   - ✗ "基于template.docx，标题/表题/图题自动编号，正文仿宋12pt。"
   - ✓ "水科院报告体例：标题、表题、图题自动编号。"
3. **不暴露内部概念**：节点/内容块/复制组/重复单元/注册表/兜底/槽位/指令/克隆列表组等。
   - ✗ "已导出 DOCX（N 条指令 · 克隆列表组 M）"
   - ✓ "已导出 DOCX"
4. **错误/警告也面向人**：指出"什么没成功、影响是什么"，不贴内部错误码与字段。
   - ✗ "节点「x」标题：缺少样式 heading.2" / "图「x」与文件名不一致（已按槽位嵌入）"
   - ✓ "「x」标题的样式未生效，已按默认样式输出" / "「x」题注与文件不一致，已按顺序嵌入"
   - **失败提示要带原因**，不带原因等于让用户猜（口径见
     [DESIGN-04-工程数据与存储.md](DESIGN-04-工程数据与存储.md) 里"打不开时说什么"那一节）：
     界面上显示的那句话
     就是主进程给的那句中文结论（`该章节不允许裁剪`、`工程数据库不存在：…`），
     所以**主进程那一侧必须把面向用户的拒绝与校验写成给人看的句子**。
     驱动的原始异常（SQLite 的 `no such column`、fs 的 `ENOENT` 之类）不许直接当结论抛给界面：
     看到它说明该处少写了一句结论，按缺陷处理。
5. **同一件事只有一个词**：权限与档位的用词以 `packages/desktop/src/shared/permissionTerms.ts` 为准
   （复制／裁剪／编辑／排版，自由编辑／类型限制编辑／只读），两侧界面与拒绝语都从那里取词，
   口径见 [DESIGN-06-权限与锁.md](DESIGN-06-权限与锁.md)。
6. **状态噪音最小化**：结果提示能承载的，界面上不重复；机制状态（"已回退为文本占位导出"类）
   只保留"对交付有影响"的那一部分，且用用户语言。
7. **能力缺失提示**：某项可选能力不可用时，说清"结果是什么"与"对交付的影响"，不解释依赖、
   不引导安装外部工具、不出现技术名词。
   - ✗ "图表嵌入服务不可用，请安装 mmd2vsdx 与 Chromium"
   - ✓ "图以文本形式导出，双击编辑暂不可用"

## 自查清单（提交前）

- [ ] 文案中无 文件引用（xxx.docx / json 文件名）
- [ ] 文案中无 实现术语（Visio/VSDX/Mermaid/LaTeX/槽位/占位/转换/预览/注册表/兜底/节点/内容块）
- [ ] 每条用户文案 ≤ 一句话
- [ ] 权限与档位的词取自词表，同一个权限没有第二个说法（`pnpm check:terms` 看住）
- [ ] 失败提示带得上原因，且那句话是给人看的结论，不是驱动的原始异常
- [ ] 能力缺失提示只说结果与影响，不含依赖名/安装指引
