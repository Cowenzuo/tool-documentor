# PLAN-13 结构锁口径方案

> 结构锁现在这样：节点级三个开关（复制／裁剪／编辑），内容块级四档（不写／`type`／`keep`／`readonly`）。
> 两处说的是两件事，却混在一层里：`keep` 一档同时管"类型不能换""必须存在""位置不能动"，
> 而节点级的"编辑"名不副实，只拦得住"加块"。本文把两层的分工定死，并给出模板侧的落地清单。
> 模板侧的落地与工程编辑侧的落地分两轮做，本文只做前一阶段：字段、界面、校验与迁移口径。

## 1 分工

节点级回答"这一章能怎么动"，内容块级回答"这一块本身能不能改"。两级取交，谁更严听谁的。

### 1.1 节点级

| 开关 | 字段 | 缺省 | 管什么 |
| --- | --- | --- | --- |
| 复制 | `copyable` | false | 整棵子树能不能被复制一份 |
| 裁剪 | `deletable` | false | 这一章能不能被删 |
| 编辑 | `allowContentBlocks` | **true** | 内容块总闸：关掉整章内容块只读 |
| 排版 | `allowLayoutEdit` | **true** | 集合、顺序、类型能不能动；关掉后只能改各块的内容 |

两个"允许"类开关的缺省都是 true（不写就是放开，与今天一致）；复制与裁剪的缺省是 false（不写就是锁住，也与今天一致）。

### 1.2 内容块级

| 档位 | 写入 JSON | 改内容 | 换类型／表格的表头与列数 | 能不能删 |
| --- | --- | --- | --- | --- |
| 自由编辑 | 不写 `lock` | 是 | 是 | 是 |
| 类型限制编辑 | `"keep"` | 是 | 否 | 否 |
| 只读 | `"readonly"` | 否 | 否 | 否 |

位置（顺序）不在块档位里：那是节点级「排版」的事。所以块档位只剩三个问题：内容能不能改、类型能不能换、还在不在。

### 1.3 落到界面的权限

| 编辑 | 排版 | 块档位 | 改内容 | 换类型／表头 | 加块 | 删块 | 移块 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 关 | — | — | 否 | 否 | 否 | 否 | 否 |
| 开 | 关 | 只读 | 否 | 否 | 否 | 否 | 否 |
| 开 | 关 | 类型限制编辑 | 是 | 否 | 否 | 否 | 否 |
| 开 | 关 | 自由编辑 | 是 | 否 | 否 | 否 | 否 |
| 开 | 开 | 只读 | 否 | 否 | 是 | 否 | 是 |
| 开 | 开 | 类型限制编辑 | 是 | 否 | 是 | 否 | 是 |
| 开 | 开 | 自由编辑 | 是 | 是 | 是 | 是 | 是 |

排版关掉时"类型限制编辑"与"自由编辑"结果相同（都只剩改内容）。两种写法都留着，作者按语义选。

## 2 值域不动

三档正好落在现有的 JSON 取值上，所以模板库不需要批量改写：

| 档位 | JSON 值 | 与今天的关系 |
| --- | --- | --- |
| 自由编辑 | 不写 | 同今天的"不锁" |
| 类型限制编辑 | `"keep"` | 值不变，语义微调：位置那一半挪给「排版」 |
| 只读 | `"readonly"` | 不变 |
| 作废 | `"type"` | 类型固定但可删，新口径没有这一档；读到报提示并给就地改的动作 |

## 3 模板侧改动

1. 节点区三个开关变四个：复制／裁剪／编辑／排版，两个新语义的悬停提示按本文重写；
2. 块卡片头的锁下拉变三档，读到 `"type"` 显示为旧档位并给一个"改成类型限制编辑"的动作；
3. 作者的挪块与删块**不再按锁置灰**：锁是给模板使用者设的，作者定义顺序天经地义；
4. 卡片上的锁标记改成 `类型限制` 与 `只读`（旧档位标 `旧档位`）。

## 4 校验

主进程（`packages/templates`）与渲染层本地规则（`templateValidate.ts`）各一条，规则同源：

| 规则 | 级别 | 说什么 |
| --- | --- | --- |
| `node.allowLayoutEdit.invalid` | error | `allowLayoutEdit需为布尔值` |
| `block.lock.legacy` | warn | `lock 档位 type 已作废 · 改成 keep 或去掉` |
| `block.lock.layout` | warn | `keep` / `readonly` 的块，所在节点排版开着：`位置不锁 · 用户可以挪` |
| `block.lock.invalid` | error | 取值不属于认得的那几个（现在按自由编辑处理，文案跟着改） |
| `block.nodeField.misplaced` | error | 节点级字段清单加上 `allowLayoutEdit` |

`block.lock.layout` 这条就是旧模板的过目通道：作者按提示决定哪些章节该关掉「排版」。

## 5 迁移

- 值域不动，**不批量改库**；
- 旧 `type` 逐处由作者定（改 `keep` 或去掉）；
- 位置意图：`keep` 原来含"位置不能动"。批量给这些节点写 `allowLayoutEdit: false` 会把整章也变成不能加删块，
  比今天更严，所以不批量写，改由 `block.lock.layout` 提示，作者在界面上按节点决定；
- 样例模板里的 `type` 与 `allowLayoutEdit` 直接改（自建样例，随本文一起落）。

## 6 这一轮不做

工程编辑侧的取交校验（写入侧按「编辑／排版」与块档位共同判定）、编辑器界面的置灰与文案、
克隆体里的块锁如何处理、章节标题是否也受「编辑」管、用户侧换类型的入口、
导出时"锁定块缺失"的警告、`copyGroupId` 复制组的去留。

## 7 验收

1. 模板编辑器里四开关与三档下拉可用，旧档位有提示与就地改的动作；
2. 三条新校验按预期报，两处（主进程与渲染层）口径一致；
3. 两处模板库加载与既有导出组合不回归；
4. 作者挪块、删块不再被锁挡住。
