# PLAN-16 工程编辑侧权限落地

> 状态：已实施。范围是 PLAN-13 第 6 节留给工程编辑侧的那一轮：把「排版」传到工程里，
> 按「编辑 × 排版 × 块档位」取交判定，界面按同一份判定置灰。
> 上一轮（PLAN-15）统一的是词，这一轮落的是判定。

## 1 这一轮做什么

PLAN-13 把节点级「编辑」与「排版」的分工定死了，但工程侧只认「编辑」一项，块档位管着顺序；
模板作者把「排版」关掉，用户那边毫无感觉。这一轮把两件事补齐：

1. 「排版」从模板传播进工程：节点字段、库表列、DTO、与撤销快照；
2. 写入侧按 PLAN-13 第 1.3 节那张表取交；
3. 界面按同一份判定置灰，理由与拒绝语同一批说法。

## 2 取交口径（落地版）

| 编辑 | 排版 | 块档位 | 改内容 | 换类型／表头列数 | 加块 | 删块 | 移块 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 关 | 任意 | 任意 | 否 | 否 | 否 | 否 | 否 |
| 开 | 关 | 任意 | 是 | 否 | 否 | 否 | 否 |
| 开 | 开 | 只读 | 否 | 否 | 是 | 否 | 是 |
| 开 | 开 | 类型限制编辑 | 是 | 否 | 是 | 否 | 是 |
| 开 | 开 | 自由编辑 | 是 | 是 | 是 | 是 | 是 |

与 PLAN-13 第 1.3 节一致的地方：位置归排版管，所以**排版开着时 keep 与 readonly 也能挪**，
这是这一轮最明显的行为变化（原来那两档的位置是钉死的）。
不一致的地方：PLAN-13 那张表把"加块"在排版关时记为否，本文照此执行——
排版关掉就只剩改各块的内容，"集合"三个字就是加与删。

判定只写一份：`packages/desktop/src/shared/permissionTerms.ts` 的 `blockPermissions`，
写入侧（`project-service`）与界面（`NodePage`、`BlockCard`）都调它，拒绝语也从这里取，
所以置灰提示与写入侧拒绝的话不会各说各话。

## 3 传播

| 件 | 落点 |
| --- | --- |
| 模板 | `TemplateNodeDef.allowLayoutEdit`（缺省 true），解析与实例化各一处 |
| 文档树 | `DocumentNode.allowLayoutEdit`，深拷贝、快照与恢复三处一起带上 |
| 库表 | `node.allow_layout_edit INTEGER NOT NULL DEFAULT 1`；老库读时按缺省 true，保存时补列 |
| 通道 | `NodeDto.allowLayoutEdit` |
| 根节点 | 保存时四个开关一起写（原来根行只写标题与描述，根上的权限一保存就丢） |

老库没有这一列：读的一侧按实际列名问一遍（与 `project` 表那次同一个做法），
写的这一侧在保存时补列 —— 所以打开老工程不会因为缺列而报错，第一次保存就补齐了。

## 4 界面

- 标题下那排标签多一枚「排版」，只列能做的事这一条不变；
- 加内容与"在此插入"两个入口只在排版开着时出现；排版关掉时整章只剩改内容；
- 块卡片：上下移看排版，删除看"排版 + 块上没有锁"，理由按挡在最前面的那一条说；
- 表格编辑器：行数、列数、表头与合并开关按"排版 + 块上没有锁"置灰，单元格内容照常可改
  （只读那一档内容也锁着）。

## 5 还留着没做的

| 件 | 为什么 |
| --- | --- |
| 用户侧换类型的入口 | 换类型要定"内容怎么搬"（文本转列表？表转文本？），那是新功能的取舍，不是取交的事。排版开着时"删一块再加一块"就是同一件事，写入侧已按矩阵放行 |
| 导出时"锁定块缺失"的告警 | 工程树里的节点与模板节点之间没有身份对应（可以复制、改名、挪位置），做不了可靠的比对；要做得先给节点加模板来源标识，另立方案 |
| `copyGroupId` 复制组的去留 | 它现在只有字段与一条校验，没有行为；删它要动模板库、库表与校验，属单独一件事 |

## 6 已经定了的两件小事

- **克隆体里的块锁**：跟着块一起复制。复制一章得到的是同一个模板形态的另一份，锁不解除；
- **章节标题与编制说明不受「编辑」管**：「编辑」是内容块总闸，标题与编制说明是这一章自己的字段，
  什么时候都能改。真要连标题也锁，那是给节点再加一档的事。

## 7 自检

| 命令 | 覆盖 |
| --- | --- |
| `pnpm check:locks` | 从 19 项扩到 31 项：编辑关整章只读、排版关只剩改内容，块档位的放与拦，表格形状（表头与列数）算形状不算内容 |
| `pnpm check:terms` | 从 17 项扩到 22 项：取交只写一份（词表里定义、写入侧与界面都调它），旧说法一个不剩 |
| `pnpm check:terms:ui` | 从 10 项扩到 18 项：排版那一枚标签按开关出现，排版关的章节没有加内容入口、块挪不动也删不掉、表头行列不给改而单元格照常能改，keep 与 readonly 在排版开着时能挪 |

## 8 验收

1. 五种节点权限组合在服务侧的拦与放全部符合第 2 节的表；
2. 界面上标签、置灰与提示与写入侧一致，排版关的章节看不到加内容入口；
3. 老工程（没有 `allow_layout_edit` 列）照常打开，保存后补列且权限写对；
4. 既有八份自检全绿，导出链路不受影响。
