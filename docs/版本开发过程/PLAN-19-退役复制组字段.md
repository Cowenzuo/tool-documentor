# PLAN-19 退役复制组字段

> 状态：已实施。把 `copyGroupId` 这个字段从产品、工具、文档与模板里清掉。
> 它从旧版数据模型里一路搬过来，却一处行为都没有：留着只会让人以为它在管事。

## 1 它是什么，为什么退役

`copyGroupId` 是旧版产品留下的**重复单元标记**：同一父节点下同组的节点算"一份重复单元的多份"，
作者用它标 `module-group`、`key-tech`、`perf-target-func` 这类位置。重写版把它整个搬了过来：

| 层 | 现状（退役前） |
| --- | --- |
| 模板 JSON | 5 套结构模板 24 处在用 |
| 文档树 | `DocumentNode.copyGroupId`，深拷贝与快照照抄 |
| 库表 | `node.copy_group_id` 列 |
| 通道 | `NodeDto.copyGroupId` |
| 校验 | 一条规则：`copyGroupId 在，copyable 不是 true · 复制不了` |
| 行为 | **一处都没有**：界面不显示、复制不看它、导出不看它；`copyGroupCount()` 零调用方，死代码 |

复制这件事本身早就闭环了，闭环的口径是"一章一份、原样复制"（PLAN-18）：复制只看 `copyable`
与整棵子树，从来不问组。所以这个字段既不是复制机制的一部分，也没有任何别的用处。

## 3 老数据怎么办

- **工程库里的那一列留着不删**：程序不再读写它，新建的库也没有这一列；老库留着这一列是为了
  **已经打包出去的旧版本还能打开这些工程**（旧版的读语句里有它，删列会让旧版直接报缺列）。
  下一次保存会把它写成空串，等于自然清掉。
- **模板里的 24 处已经清掉**：模板是"以后新建工程"的来源，留着它会继续往新工程里写。
- 字段退役了，但**"重复单元"这个写作概念还在**（作者心里的一节一份）。哪天要在编辑侧做成能力
  （例如"再加一个模块组"一次复制整份单元），那是新方案，字段另起，不复用这个已经空转的名字。
