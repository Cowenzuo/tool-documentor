# PLAN-10 撤销与重做方案

> 现在的编辑器没有撤销：保存是全量重写式，一次误操作只能靠手工改回来。
> 本文定下撤销的口径、什么算一步、程序要改哪些地方，以及验收怎么做。
> 规格定稿后才动手。

## 1 口径

- 撤销栈是**会话级的**：跟着当前打开的工程走，不落库、不跨工程、不跨进程重启。
- **一步 = 一次用户可感知的编辑动作**，不是一次按键，也不是一次 IPC 往返。
- **撤销不改数据库**：改动退回内存与界面，数据库仍只在保存时全量重写。保存之后照样可以继续
  往前撤销，再保存一次就把数据库一起退回，这与 Word 的口径一致。
- 被拒绝的操作不入栈：服务端因为模板锁、表格形状、位置越界拒绝的写入，等于没发生。
- 撤销与重做自身不入栈，重做栈在新编辑发生时清空。

## 2 什么算一步

| 操作 | 合并规则 |
| --- | --- |
| 内容编辑：文本、列表项、表格单元格、代码、公式、图片题注 | 同一块同一字段连续编辑按停顿合并，600 毫秒无操作即封口；离开该块、切换章节或做别的操作立即封口 |
| 章节标题、编制说明 | 同上，按停顿合并 |
| 结构化操作：加内容、删内容、移动内容、加章节、删章节、复制章节、导入图片 | 一次操作一步，不合并 |
| 表格补齐合并、缩减行列 | 一次操作一步；缩表带确认对话框，取消不入栈 |
| 模板实例化新工程、导入实例 JSON、导出、设置、模板目录、界面状态 | 不入栈 |

合并的判据是**同一编辑对象加时间窗口**：对象变了（换了块、换了章节）或窗口过了就封口，
所以"打一段字，停一下，再打一段"是两步，"一口气打完"是一步。

## 3 快照怎么存

快照按**受影响的子树**存，不存整棵树：

| 操作 | 快照对象 |
| --- | --- |
| 内容块增删改移、导入图片 | 该章节节点的子树 |
| 章节标题、编制说明 | 该章节节点的子树 |
| 加章节、删章节、复制章节 | 父节点的子树 |

每条栈记录同时留**改动前**与**改动后**两份子树快照，撤销写回前者、重做写回后者，
不需要为每个操作单独实现反向指令。理由：内容块没有稳定 id、按下标记录反向会错位，
而子树快照只认节点身份，节点 id 本来就稳定。

代价与上限：一条记录的体积与子树成正比，上限取**100 步或累计 32 MB，先到先限**，
超出从最旧开始丢；单条自身超过 32 MB 时只保留该条，保证最后一步总能撤销。

不采用整树深拷贝：真实工程里一个章节的子树通常只有几 KB，而整棵树会随章节数增长，
100 步下来内存不可控。

## 4 程序要改的地方

1. `packages/core` 新增 `history.ts`：通用快照栈，只认"改动前 / 改动后 / 合并键 / 时间戳"，
   提供 `push`、`undo`、`redo`、`canUndo`、`canRedo`、`size`、`clear`，纯函数无 I/O，可单测；
2. `packages/desktop` 主进程 `ProjectService`：在每个会改树的方法入口记录快照，操作成功后
   入栈，抛错时丢弃该条；提供 `undo()`、`redo()`、`historyState()`；
3. IPC 新增三条通道：`history:undo`、`history:redo`、`history:state`。撤销与重做返回与打开
   工程同一形状的载荷（`info` 加 `root`）外加选中项提示，渲染层整棵替换，不另造增量协议；
4. 渲染层 `AppContext`：新增 `undo()`、`redo()`，撤销前先 `flushAll()` 把防抖中的编辑落定，
   拿到新树后替换会话状态并按提示恢复选中；历史状态随操作刷新，驱动按钮置灰；
5. 主进程 `ipc.ts` 与 `shared/project.ts` 补通道常量与类型；`preload` 暴露 `history` 分组。

## 5 界面与快捷键

- `Ctrl+Z` 撤销，`Ctrl+Shift+Z` 与 `Ctrl+Y` 重做；键位在按下时 `preventDefault`，一律走应用级撤销；
- 节点页工具栏加「撤销」「重做」两个按钮，栈空时置灰；悬停提示写明最近一步动作，
  例如「撤销：删除内容」「重做：修改标题」；
- 文本框里按 `Ctrl+Z` 也走应用级撤销，不是文本框自带的逐字撤销。取舍是明确的：
  让浏览器自己撤销文字会让界面与内存里的树分叉，分叉之后保存下去就是脏数据；
  逐字撤销的损失由 600 毫秒合并窗口兜住，一次撤销退掉一小段输入，不是整篇；
- 撤销后选中的章节若已不存在（例如撤销掉"加章节"），选中退回它的父节点；章节还在就保持不动。

## 6 与既有能力的关系

- **保存**：保存不封口撤销栈，也不清栈；保存后继续撤销、再保存即可一起退回数据库；
- **模板锁**：锁随块数据走，撤销与重做天然带回原档位，不需要额外搬运；
- **防抖编辑**：撤销与重做前先冲刷待落地的编辑，保证栈上的顺序与用户看到的顺序一致；
- **表格合并**：补齐合并不动单元格内容，撤回时跨度过河拆桥地退回去，数据不受影响；
- **工程开关**：打开、关闭、切换工程时清栈，历史不跨工程。

## 7 非目标

- 不做跨工程、跨会话的持久化历史；
- 不做逐字符撤销，也不做"撤销历史"面板；
- 不做协作或多人合并；
- 不把撤销做进 CLI 与导出链路。

## 8 验收

- 单测：`history.ts` 的合并、上限、清栈、重做失效，覆盖停顿封口与对象切换封口；
- E2E 追加断言：内容编辑后撤销内容回退且再重做恢复；删内容后撤销整块回来；删章节后撤销
  章节连同子树回来且选中恢复；新编辑后重做按钮置灰；保存后撤销再保存，重新打开工程是撤销后的
  状态；`Ctrl+Z` 与工具栏按钮两条路径各验一次；
- 手工：真实工程里连续输入、缩表、补齐合并、导入图片各撤一次，确认界面、树与数据库三处一致。

## 9 实施顺序

1. `core/history.ts` 与单测；
2. 主进程快照钩子与三条 IPC 通道；
3. 渲染层状态、快捷键与按钮；
4. E2E 断言与手工验收；
5. 文档：`docs/AI开发约定/项目特定规范.md` 补验收口径，本方案归档进 `docs/版本开发过程/README.md`。
