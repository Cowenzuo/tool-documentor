# PLAN-07 题注编号改域方案（表题/图题 STYLEREF + SEQ）

> 状态：**已实现并 Word 实测通过**。触发问题：
> "表题没有和图题一样使用交叉引用？亦或者序号什么的，我看表题是手打的。"

---

## 1. 改前状态（问题）

| | 实现 | 结果 |
|---|---|---|
| 图题（229） | 样式 `capF` 带 `numPr ilvl=6 numId=1`，文本只有标题 | 多级列表自动编号 → 图4.1.1-1 |
| 表题（38） | 样式 `capT` 无 numPr，文本自带「表4.1-1 …」 | **手打编号** |

全文域代码为 0，因此两者都不是 Word 的题注域——图题是"列表自动编号"，表题是纯文本。

## 2. 为什么表题不能直接照抄图题的多级列表

`numId=1` 被标题（ilvl 0–4）与图题（ilvl 6）共用。表题位于「标题 2 之后、第一个标题 3 之前」，
若挂 ilvl 6，Word 会**补齐中间层级**（把 level 3 置 1），紧随其后的第一个标题 3 被顶成 4.1.2
（实测见提交 `88758fd`）。图题当前没暴露该问题，只是因为图恰好都在标题 3 之后——
一旦有图落在「标题 2 之后、标题 3 之前」，同样会顶高标题计数。

结论：**任何与标题共用多级列表的题注层级都会污染标题计数**，与 ilvl 取值无关。

## 3. 方案：题注域

```
表题：表{ STYLEREF "标题 2" \n }-{ SEQ 表 \* ARABIC \s 2 }  标题
图题：图{ STYLEREF "标题 3" \n }-{ SEQ 图 \* ARABIC \s 3 }  标题
```

- `STYLEREF <样式> \n` 取最近一个该样式段落的编号（即章节号）；
- `SEQ <标签> \* ARABIC \s N` 在该层级标题处重启，得到本节内的序号；
- 两者都不占用标题多级列表，**标题计数不再被污染**；
- Word 将 SEQ 标签（图/表）识别为题注标签，交叉引用对话框可用；
- 导出时把算好的编号写进域缓存值（`w:fldSimple` 的子 run），打开即显示正确，F9 可刷新。

### 关键实现点

| 位置 | 改动 |
|---|---|
| `packages/templates` | `captionNumbering` 增加 `field` 模式、`chapterStyleNames`（层级→本地化标题样式名）、`headingStarts`（骨架 numbering.xml 各层级起始号，报告从第 4 章起编号要用） |
| `packages/docx` serializer | 维护标题计数与每节题注序号；field 模式剥离手写序号并产出 `InsertCaption` 指令 |
| `packages/docx` writer | 渲染 `w:fldSimple`（STYLEREF / SEQ）+ 缓存值 |
| 模板骨架 | `capF` 去掉 `numPr`；`numbering.xml` 去掉 ilvl=6 上的 `w:pStyle=capF` 绑定（否则样式仍会被列表自动编号） |

### Word 域语法实测（重要）

在本机中文 Word 上实测：

| 写法 | 结果 |
|---|---|
| `STYLEREF 4 \n`（styleId） | ✗ 文档中没有指定样式的文字 |
| `STYLEREF "heading 3" \n`（OOXML 里的 w:name） | ✗ 找不到样式 |
| `STYLEREF "标题 3" \n`（界面本地化名） | ✓ 4.1.1 |

→ STYLEREF 只认**样式在界面上的本地化名称**，因此由模板的 `chapterStyleNames` 显式给出
（中文 Word 为「标题 N」）。这也是 Word 自己写题注时采用的形式。若模板显式给空串，
该部分退化为导出时算好的静态章节号文本（跨语言环境更稳）。

## 5. 非目标 / 已知边界

- 未做"正文里插入图表交叉引用"的编辑功能（域已就绪，属后续 UI 功能）；
- STYLEREF 的样式名依赖本地化；跨语言打开并 F9 更新时可能报错（缓存值仍可正常显示）；
- WPS 对 STYLEREF/SEQ 支持较弱，可能只显示缓存值而不自动更新。
