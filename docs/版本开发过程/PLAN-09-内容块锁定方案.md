# PLAN-09 内容块锁定方案

> 现在只有节点级锁：能不能复制、能不能删除、能不能加内容。这不够。
> 模板规定的不只是"这个标题下有一个块"，有时是"这个标题下必须是一张有序列表，
> 类型不能改、块不能删"。本文定下这个能力的口径与模板作者要遵守的契约，
> 并给出模板工作区的改动清单。

## 1 口径

锁分三档，写在**模板块定义**上，实例化时跟着块进工程数据：

| 取值 | 含义 | 能改内容 | 能改类型 | 能删除 | 能上下移动 |
| --- | --- | --- | --- | --- | --- |
| 不写 | 不锁，与现在完全一样 | 是 | 是 | 是 | 是 |
| `"type"` | 只锁类型：必须是这一类块 | 是 | 否 | 是 | 是 |
| `"keep"` | 类型锁住且必须存在 | 是 | 否 | 否 | 否 |
| `"readonly"` | 整块只读：内容也由模板给定 | 否 | 否 | 否 | 否 |

`"keep"` 是推荐的默认档：它表达"这个槽位必须有这么一类内容"，正是模板最常想说的那句话。
`"readonly"` 留给模板自带、不许改的固定说明文字。

三个决定项：

1. **声明写在模板节点定义的 `contentBlocks[]` 里**，字段名 `lock`，取值如上表；
2. **锁跟着块走，不按下标绑**。工程里的内容块没有稳定 id，只按下标记录锁会在插入/
   删除之后错位，锁跑到别的块上。所以锁写进块数据本身；
3. **程序侧先兼容读取**：没写 `lock` 的模板与老工程一律视为不锁，行为一点不变。

## 2 模板作者契约

在结构模板 JSON 的节点定义里，给需要锁的块加 `lock`：

```json
{
  "nodeType": "section",
  "title": "标识",
  "headingLevel": 2,
  "contentBlocks": [
    { "type": "orderedList", "lock": "keep", "items": ["", "", ""] },
    { "type": "text", "content": "本节按下列条目填写。" }
  ]
}
```

约定：

- `lock` 只对**块定义**有效，写在节点上无效；节点级仍用现有的
  `copyable` / `deletable` / `allowContentBlocks`；
- 取值只认 `"type"`、`"keep"`、`"readonly"` 三个字符串，其它值按不锁处理并记一条加载警告；
- `lock: "readonly"` 的块，模板给的初始内容会被当作定稿：编辑器里只显示不可改；
- `lock: "keep"` 的块可以给空内容，用户负责填写，但不能删、不能改类型、不能挪位置。

## 3 程序侧要改的地方

1. `packages/core` 的 `ContentBlock` 增加可选字段 `lock`，随 `props_json` 落库与读回；
   老数据缺省无此字段，按不锁处理；
2. `packages/templates` 解析模板块定义时带上 `lock`，非法值记警告按不锁处理；
3. `packages/desktop` 编辑器：锁定块显示锁标记；类型选择器与删除、上下移按钮按档位置灰，
   并在提示里说明原因（沿用"只列能做的事"的说法，不写"不可编辑"这类喊话式文案）；
4. 写入侧校验：类型被锁的块收到改类型的更新时拒绝并给出原因；`keep` 与 `readonly` 档的块
   拒绝删除与移动，`readonly` 档还拒绝改内容与换图。锁定档位以库里的块为准，写入方带什么
   档位都不改变它，界面按档位置灰只是提示，最终以写入侧为准；
5. 导出：锁定块缺失时给警告，不阻断导出；
6. 文档：`docs/WORD解压结构研究/表格与合并.md` 不涉及，模板作者契约以本文为准。

## 4 给模板工作区的改动清单

目标仓库：`tool-documentor-template`。

1. 打开 `packages/structures/*/` 下每个结构模板的 JSON，找出"必须包含某一类内容"的节点。
   判断依据：该节点的 `contentBlocks` 里已有某个块，且其类型是这份文档体例的硬要求，
   例如"标识"下必须是有序列表、"术语"下必须是表格；
2. 给这些块加 `lock`：类型必须固定但用户可以删掉再自己加回来的场景用 `"type"`；
   必须存在、不许删也不许挪的用 `"keep"`；模板给定不许改的说明文字用 `"readonly"`；
3. 不要动其它字段：`type`、`content`、`items`、`headers`、`data`、`caption` 一律保持原意；
4. 改完自测：
   - 结构模板 JSON 仍是合法 JSON，字段位置与缩进与既有条目一致；
   - 每个新加的 `lock` 取值只在这三个之内；
   - 在程序的"新建工程"里选该模板新建一次，锁定块的锁标记能显示出来，
     删除按钮与类型选择器按档位置灰；
5. 如果某个节点你判断"内容也必须固定"，把它标成 `"readonly"` 之前先确认：
   这份文档的用户真的不需要填任何东西。拿不准就用 `"keep"`。

## 5 兼容与顺序

程序侧先落地字段与读取，模板再逐步加标记；两边不同步也不会出错：

- 程序已支持而模板没加 → 与现在完全一样；
- 模板已加而程序未支持 → 程序忽略未知字段，内容照常读写，只是不锁。

因此模板工作区可以先行修改，不必等程序这一版发出去。
