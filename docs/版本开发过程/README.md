## 读法

想弄清某个设计的来龙去脉，按 PLAN 编号顺着看：方案在前，整改在后。
要动手改代码，不要只照这些文档改，结论以
`docs/WORD解压结构研究/` 为准，那里的条目都带实测依据。

## 边界

- 本区文档保留当时的写法与结论，包括后来被推翻的判断；
- 与新结论冲突时，以新文档为准，并在新文档里写清取代了哪一条；
- 文档里出现的内部阶段编号，仅在本区内有意义；
- 会话与整理时提到的本机绝对路径已改成通用说法，只留上游检出的位置一处，
  那是对接时必须知道的信息；被改掉的原文仍可从 git 历史里查到。
