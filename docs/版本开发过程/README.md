# 版本开发过程

> 名字还叫"版本开发过程"，里面装的是**当前**的设计与口径：产品现在是什么样、为什么这样、
> 什么情况下会踩坑、红线在哪。
>
> **过程记录不留**：当初怎么发现问题的、哪一轮改的、验收了什么，这些从 git 历史里查。
> 留旧的对照没有意义，只会让人分不清哪一版还算数。

## 怎么读

- 想弄清某个取舍 → 看 DESIGN 系列，一篇管一块；
- 想知道某个词该怎么写 → [产品文案口径.md](产品文案口径.md)；
- 想知道还开着什么事、先做哪个 → [待办与优先级.md](待办与优先级.md)；
- 想知道 WORD 包内部到底怎么写 → 去 `docs/WORD解压结构研究/`，那边是唯一事实源，这里只指过去；
- 想知道红线与验收门禁的正文 → `docs/AI开发约定/项目特定规范.md`。

## 边界

- 文档写的是**当前状态**：改了代码就改文档，不留"上一版怎么写"的对照；
- 「已讨论、暂不实施」的功能立项不进仓库，由维护者在本机保存，
  仓库里只留 [待办与优先级.md](待办与优先级.md) 这份索引；
- 红线、验收门禁、文档归属的正文都在 `docs/AI开发约定/` 下，这里不重复；
- 需要"当初为什么"这类来龙去脉时，从 git 历史里翻被删掉的那批过程文档。
