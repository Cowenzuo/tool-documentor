## 3. 产权/版权规避

### 3.1 不依赖「Word 原生样本」── 辅助流改为公开格式常量

旧版 `visio_ole.py` 从 `docs/…/测试对比.docx`（含真实文档内容的对照样本）提取
`\x01Ole / \x01CompObj / \x03ObjInfo` 三个 CF 辅助流。本实现**不再读取任何样本文件**：

- `\x01Ole`（20B）、`\x03ObjInfo`（6B）：MS-CFB/[MS-OLEDS] 公开结构的固定格式字节；
- `\x01CompObj`：按 CompObj 布局程序化构造（版本头 + CLSID + ANSI 长度前缀串）；
  CLSID `{00021A15-0000-0000-C000-000000000046}` 与 ProgID `Visio.Drawing.15` 是
  Microsoft 公开注册标识符（注册表/公共规范值），非版权内容；
- 开发期仅用现有样本做**一次性比对自检**（见 §6 互操作验证），任何样本字节/文本均未入库。

### 3.2 不打包 Visio 官方模具/程序集

mmd2vsdx 的母版资产（官方 Stencil masters）按上游设计本来就不带包（gitignore/勾销），
运行时四级供应：

1. `configureStencils({ assetFile })` —— 用户自备预生成资产 JSON；
2. `configureStencils({ stencilDir })` —— 用户自备官方模具目录（现场提取）；
3. 缺省自动搜寻本机 Visio（`%LOCALAPPDATA%\mmd2vsdx\` 本地缓存，只在本机生成）；
4. `useConnectorMaster=false` —— **零资产纯本地几何**（无需 Visio/模具；连接线失去
   内置线型切换 UI，功能上以文档说明）。

均属「运行时前置条件」，不随软件分发 → 无版权再分发风险。

### 3.3 预览图 = 上游转换的附带物（本工程不产预览）

**分层修订（discussion 定案）**：预览图与 VSDX 同源同风格，属"图转换"职责，完全由
`mmd2vsdx` 工程产出。本工程只按"假定预备的 VSDX 就是交付格式"消费：

- `convertText` 的返回可附 `previewBase64`(+`previewExt: 'png'|'emf')`——documentor 将其
  嵌入 `<v:imagedata>`（Word 原生支持 png/emf）；
- 回退链：① 无 `previewBase64` 但暂存区存在 `<stem>.png/.emf`（上游另存文件的外部流程）→ 用之；
  ② 都没有 → **无预览嵌入**（OLE 对象仍有效，Word 显示图标），不报错、不中断；
- **本工程已移除旧版"Visio COM/EMF 渲染"（preview.ts / renderVsdxPreviews）**——那是以
  本机 Visio 为前置的临时方案，与"生成侧零 Word/零 Visio"目标冲突，正式线路由上游接管。

## 4. 结构规范（分层与依赖方向）

```
apps/desktop（UI/IPC/CLI 编排）
  └─ @documentor/docx（序列化 + collectMermaidFigures + attachFiguresToDocx 管线）
       ├─ @documentor/postprocess（CFB/OLE 容器、vsdx 包围盒/页面修补、OOXML 嵌入、EMF 预览）
       │    └─ jszip（唯一第三方依赖，MIT）
       └─ mmd2vsdx（仅动态 import，外部 link:）
```

- `postprocess` 不感知文档树/样式/模板——纯 docx/VSDX 字节装配，可独立复用与测试；
- `docx` 是唯一编排层：收集（与序列化同构遍历）→ 转换（可注入）→ 暂存 → 预览（可注入）→
  嵌入 → `<stem>-嵌入.docx`；
- 双出口打包与全仓一致：`import → src`（vitest/vite）、`require → dist`（CJS, tsc build）；
  库包无 `"type":"module"`（dist CJS），electron-vite 外部化依赖。

## 5. 兼容性修复记录（M7 验证中发现并修复的两处 pre-existing 缺陷）

M7e 在做 Word 真机验证时发现**所有导出**（含纯占位版）被 Word 判为「文件可能已损坏」，
逐层二分（minimal 打包 ↔ 骨架打包 ↔ 部件切除 ↔ XML 属性消元）定位并修复：

1. **`packages/docx/src/writer.ts`**：`XML_HEAD` 的 `mc:Ignorable="w14 w15 wp14"` 引用了
   **未声明**的前缀 `wp14`（属 MCE 非法），Word 一律拒开。修复：声明
   `xmlns:wp14="http://schemas.microsoft.com/office/word/2010/wordprocessingDrawing"`。
   （回退验证：仅删掉该属性即 100% 可打开；仅加声明同样可打开。）
2. **本地 438C 骨架 `word/styles.xml`**（localtest，gitignored）：`mc:Ignorable="w14"`
   同样引用未声明前缀，已就地补齐 `xmlns:w14` 声明（438C SRS 一并修复；修复前后 Word 行为
   ——修复后纯导出/嵌入版均免修复直接打开）。

> 两处同根：`mc:Ignorable` 前缀必须与 `xmlns` 声明一一对应，这是 Word 打开即校验的
> MCE 规则，XML 解析器（ElementTree）不会报错，只有 Word 拒绝。
