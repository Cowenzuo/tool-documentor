# 包结构与写入方式

> 本工程不生成 docx，而是**改写**样式模板自带的 docx 骨架。理由很直接：模板里的
> 页面设置、页眉页脚、样式表是用户单位的版式资产，重新生成一份必然走样。
> 本页说明包里有哪些部件、哪些可以重写、哪些必须原样带过去。

## 1. 包布局与本工程的处置

| 部件 | 作用 | 本工程 |
| --- | --- | --- |
| `[Content_Types].xml` | 声明各扩展名的内容类型 | 仅在新增媒体或对象时追加 `Default` |
| `_rels/.rels` | 包级关系，指向主文档 | 原样保留 |
| `word/document.xml` | 正文 | **整体重写**，只保留结尾的 `sectPr` |
| `word/styles.xml` | 样式定义 | 原样保留 |
| `word/numbering.xml` | 编号定义 | **重写**，为列表组克隆编号 |
| `word/_rels/document.xml.rels` | 正文的关系表 | 追加图片与对象关系；骨架整份缺此部件时补一份，并把 styles 与 numbering 的关系一并补出 |
| `word/media/*` | 图片媒体 | 新增，文件名按 `imageN.ext` 递增 |
| `word/embeddings/*` | 嵌入对象 | 新增，OLE 复合容器 |
| `docProps/`、`customXml/`、`word/theme/` | 文档属性与主题 | 原样保留 |

## 2. 写入流程

两步，中间用一层指令序列隔开，好处是调试时可以只看指令、不看 XML。

1. **序列化**：文档树按深度优先走一遍，产出指令序列。节点标题出标题段，内容块按类型出
   段落、表格、图片或题注。指令是纯数据，不含 XML。
2. **打包**：读骨架，重写正文与编号，把指令渲染成 OOXML，再连同新增媒体压成 zip。

包内压缩参数固定，同一输入两次导出的字节一致。

## 3. 部件级不变量

这些是实测踩出来的，不遵守就会出问题：

- `sectPr` 必须原样保留并放在 `body` 末尾，它是页面尺寸与页边距的唯一来源；
- 命名空间只在根元素声明一次。重复声明 `wp` 会让 Word 拒绝打开；
- `mc:Ignorable` 里列出的前缀必须在同一元素上声明过，否则 Word 报文件损坏；
- 骨架里除 `document.xml` 与 `numbering.xml` 之外的部件逐字节带过去，不做解析再序列化，
  避免属性顺序与空白被改写。

依据：实测。导出后经 Word 打开，无修复提示，`sectPr` 与页面设置与骨架一致。

## 4. 列表编号的克隆

同一份文档里，不同列表要各自从 1 开始，所以每个列表组要独立编号。

- 每个列表组克隆一个 `abstractNum`，配一个新的 `numId`，组内所有项共用；
- 克隆时重写 `nsid` 与 `tmpl`，让 Word 认为它们是不同的编号定义；
- 组装顺序有硬要求：所有 `abstractNum` 必须在所有 `num` 之前。顺序错了，Word 会把
  编号解析成样式自带的编号，标题会显示成表号那类错乱结果。

依据：实测。顺序颠倒时题注显示异常，恢复顺序后正常。

## 5. 新增部件的三处登记

新增一张图片要同时改三个地方，缺一处 Word 就显示不出来：

1. 媒体文件本身，放进 `word/media/`，序号接现有最大值往后排；
2. `document.xml.rels` 追加一条 `relationships/image` 关系，`Id` 取现有最大数字加一；
3. `[Content_Types].xml` 里补该扩展名的 `Default` 声明。

同一路径的图片在文档里出现多次时复用同一份媒体与同一条关系，不重复登记。

依据：实测。229 张图的真实工程导出后，媒体数、关系数与图形数三者一致。
