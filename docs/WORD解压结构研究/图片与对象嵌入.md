# 图片与对象嵌入

> 本页说明图片怎么真正进包、流程图怎么变成可双击编辑的对象。图片与对象都走
> "新增部件加登记关系"的路子，差别在关系类型与容器格式。

## 1. 内联图片

图片段落长这样，关键是 `a:blip` 上的关系号要指向已登记的关系：

```xml
<w:p><w:pPr><w:pStyle w:val="图"/><w:jc w:val="center"/></w:pPr>
  <w:r><w:drawing><wp:inline>
    <wp:extent cx="5274310" cy="3955733"/>
    <wp:docPr id="1" name="Picture 1"/>
    <a:graphic><a:graphicData uri=".../drawingml/2006/picture">
      <pic:pic><pic:blipFill><a:blip r:embed="rId1"/></pic:blipFill>
        <pic:spPr><a:xfrm><a:ext cx="5274310" cy="3955733"/></a:xfrm></pic:spPr>
      </pic:pic>
    </a:graphicData></a:graphic>
  </wp:inline></w:drawing></w:r>
</w:p>
```

（上面的 cx/cy 是一张 800×600 的图在示例骨架下的实际取值，算法见第 2 节。）

要点：

- `w:pStyle` 放 `w:pPr` 首位，否则 Word 忽略图片段落的样式；
- 段落一并居中，`wp:inline` 表示随文排版，不用浮动锚点；
- `wp:docPr` 的 `id` 在文档内唯一，重号会让部分图片丢失；
- 关系号与媒体文件按第 5 节的三处登记走。

依据：实测。导出后 `InlineShapes` 计数与媒体数一致，Word 打开无修复提示。

## 2. 显示尺寸

尺寸单位是 EMU，一英寸 914400 EMU，一像素按 96 DPI 折算 9525 EMU，一 twip 折算 635 EMU。

**可用区域从骨架算，不写死**：读 `sectPr` 的 `w:pgSz` 与 `w:pgMar`，
可用宽 = 页宽 − 左右边距，可用高 = 页高 − 上下边距（页边距缺省按 Word 的 1440 twips；
页面尺寸缺失时整体回退 A4 + 1 英寸边距）。

缩放规则：

1. **按可用宽度铺满**，保持宽高比——300 像素的截图按原尺寸只有 3.1 英寸，在纸上偏小；
2. **低于 150 像素宽的极小图不放大**，硬拉只会糊成一片，按原始尺寸输出；
3. **受可用高度上限约束**：竖长图（如整页截图）即使宽度没超也按高度缩小，避免一张图跨好几页；
4. 两种约束同时生效时取更小的那个，宽高比始终不变。

> 旧口径是"横向超过 6 英寸（5486400 EMU）才缩"。它有两个问题：A4 正文宽约 5.77 英寸
> （8306 twips），6 英寸上限**比正文还宽**，会把图放大到越界；且小图永远不会被放大。
> 现已改为上面的算法。

图片尺寸从文件头读，不依赖外部库：PNG 取 IHDR 段的宽高，JPEG 扫 SOF 段，GIF 读逻辑屏幕
描述符。读不出尺寸时按 800 乘 520 像素的兜底值，只影响显示大小，不影响嵌入。

依据：实测。2 乘 3 像素的测试图定出 19050 乘 28575 EMU，与手算一致；示例骨架
（A4 + 左右 1800 twips）下 800×600 的图输出 5274310 乘 3955733 EMU，与"正文宽 8306 twips
乘 635"一致。

## 3. 媒体去重

同一路径的图片在文档里出现多次时，只登记一份媒体与一条关系，所有引用共用。
这样图表被多次引用时不会让包体翻倍。

依据：实测。229 张图对应 229 份媒体，没有重复项。

## 4. OLE 对象

流程图先转成 VSDX 字节，再包成 OLE 复合容器嵌进 docx。对象段的结构：

```xml
<w:p><w:pPr><w:pStyle w:val="图"/><w:jc w:val="center"/></w:pPr>
  <w:r><w:object>
    <v:shape style="width:...pt;height:...pt">
      <v:imagedata r:id="rIdIMG" o:title=""/>
    </v:shape>
    <o:OLEObject Type="Embed" ProgID="Visio.Drawing.15" r:id="rIdOLE"/>
  </w:object></w:r>
</w:p>
```

- `w:object` 是 run 级元素，必须包在 `w:r` 里，否则 Word 不激活这个对象，双击打不开；
- 预览图用 `v:imagedata`，EMF 优先，PNG 与 JPG 兜底。没有预览也能嵌入，只是显示为图标；
- `o:OLEObject` 的 `ProgID` 与复合容器里的 CLSID 要配套，用的是 Microsoft 公开标识符，
  不含版权内容。

依据：实测。生产产物里的对象在 Word 中双击可进入编辑。

## 5. 占位段与槽位对齐

流程图在序列化阶段先写成占位段，文本以 `[Mermaid` 开头。嵌入阶段按文档顺序找到这些段，
与收集到的图块一一对应。

- 对齐规则是"第 k 个占位段配第 k 张图"，两侧数量不一致时按较少的一方处理；
- 图块数量与占位段数量对不上属于内部异常，会转成用户看得懂的提示，告知有多少张按文本导出；
- 只有对不上的那些保留占位文本，其余照常嵌入。

依据：实测。单测覆盖了数量不等、图块缺失与转换失败三种情形。
