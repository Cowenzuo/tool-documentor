# 06 VSDX 缩略图与嵌入对象的呈现图

> 场景：docx 里用 OLE 对象嵌 vsdx（`<w:object>` + `<v:shape>` + `<v:imagedata>` + `<o:OLEObject>`），
> 呈现图是 `word/media/*.emf`。现象是**打开糊**，且**双击一次并保存后对象框被撑大**。
> 本文给出已实测闭环的结论：**呈现图可以自己合成（132 字节、画面全空），只要文件内三个尺寸字段自洽**。
> 依据是 2026-09-24 的单变量实测，复现口径见文末。

## 结论（一句话）

呈现图不必是 Visio 渲染件，也不必带画面。**自己能写出一张 132 字节的最小 EMF**，唯一要守的是文件内的一条自洽关系：

```
声明尺寸(rclFrame) = 图纸画布尺寸 × (LogicalDpi ÷ 参考设备dpi)
```

只要这条成立，**任意假定的"出图分辨率"都能用**，在别的机器上打开、双击、保存后对象框都不变。

## 现象

以 `04-er-1`（画布 12.052 × 8.781in）为例，嵌进 docx 后：

1. **打开就糊**：生成侧现状把 `docProps/thumbnail.emf`（raw 位图缩略图）当呈现图，
   只有几十像素却要显示成几英寸 → 等效十几 dpi；
2. **双击一次并保存后框被撑大**：实测出现过 405.30 × 295.31pt →
   **869.65 × 634.40pt（= 画布尺寸）**，以及最坏 **119.7 × 148.2 英寸**一族。

两件事是同一个动作的两面：Word 在更新对象时会**换掉呈现图**，并在那次替换里重算对象框。

## 机制（实测拟合出来的公式）

Word 换图之后，对象框按下式重算（`P_r`＝本机物理 dpi，`L_r`＝本机逻辑 dpi）：

```
新框 = 旧框 × (替换图声明尺寸 ÷ 存图声明尺寸) × (P_r ÷ 存图参考dpi) × (存图LogicalDpi ÷ L_r)
```

而替换图（Visio 现场渲的那张）的声明尺寸是：

```
替换图声明 = 画布 × (L_r ÷ P_r)
```

代入后，`P_r`、`L_r` 全部约掉：

```
新框 ÷ 旧框 = (画布 · L_r/P_r ÷ 声明) × (P_r ÷ 参考dpi) × (LogicalDpi ÷ L_r)
            = 画布 × LogicalDpi ÷ (声明 × 参考dpi)
```

⇒ **要 `新框 = 旧框`，只需 `声明 = 画布 × LogicalDpi ÷ 参考dpi`**——与机器 dpi 无关。

## 依据

### 1. 最小件：从 Visio 渲染件上一路做减法（每步单变量、人工双击）

| 形态 | 字节 | 结果 |
| --- | --- | --- |
| Visio 渲染件原样 | 84460 | 框不变 ✓（呈现图不被替换） |
| 保留骨架、画面全空 | 84460 | 框不变 ✓ |
| 只留"头 + 第 1 条 EMF+ 注释 + 结束记录" | 172 | 框不变 ✓ |
| 再去尾部 20 字节 / 再去结束记录 | 152 / 152 | 框不变 ✓ |
| 两处合并（**结构下限**） | **132** | 框不变 ✓ |
| 再删 `LogicalDpi` | 124 | **变大** ✗ |
| 再删记录体 / 只留 `EMF+` 外壳 | 116 / 104 | **变大** ✗ |
| 删掉第 1 条 EMF+ 注释 | 88 | 出问题 ✗ |

**必须保留**：`rclFrame`（声明尺寸）、`nHandles = 3`、`szlDevice` / `szlMillimeters`、`LogicalDpi`、第 1 条 EMF+ 头记录。
**可以删/清零**：尾部 20 字节、结束记录、全部绘制记录（GDI 与 EMF+）、其余 EMF+ 注释、`rclBounds` 内容、图形版本、`EmfPlusFlags`。

### 2. 公式的七行拟合（残差 ≤ 0.2%）

存图声明、参考 dpi、LogicalDpi 三个字段分别单独改，其余一律不动：

| 样本 | 存图声明 | 参考dpi | LogicalDpi | 框（写→现） | 预测 |
| --- | --- | --- | --- | --- | --- |
| 声明 = 框×1.05 | 5.9106in | 188.5 | 120 | 405.30 → 527.45pt | 527.5 ✓ |
| 声明 = 框+0.02in | 5.6492in | 188.5 | 120 | 405.30 → 551.70pt | 551.9 ✓ |
| 参考设备 = 96dpi | 7.6736in | **96** | 120 | 405.30 → 796.90pt | 797.8 ✓ |
| LogicalDpi = 96 | 7.6736in | 188.5 | **96** | 405.30 → 325.15pt | 325.1 ✓ |
| 声明 = 框 | 5.7665in | 188.5 | 120 | 415.20 → 453.00pt | 453.06 ✓ |
| 声明 = 渲染件值 | 6.2898in | 188.5 | 120 | 415.20 → 415.60pt | 415.4 ✓ |
| 声明 = 画布×0.638 | 7.6735in | 188.5 | 120 | 405.30 → 406.45pt | 406.3 ✓ |

### 3. 跨 dpi 验证：非本机组合在本人机器上照样正确

本机实际是 逻辑 120 / 物理 188.5，下面三组**都不是**本机组合，按 `声明 = 画布 × LogicalDpi ÷ 参考dpi` 写：

| 样本 | 参考设备 | LogicalDpi | 声明 | 框（写→现） | 倍数 |
| --- | --- | --- | --- | --- | --- |
| D1 | 96dpi（1920×1080px / 508×286mm） | 96 | 画布 × 1.0000 | 405.30 → 406.30pt | ×1.0025 ✓ |
| D2 | 144dpi（2880×1620px / 508×286mm） | 96 | 画布 × 0.6667 | 405.30 → 406.30pt | ×1.0025 ✓ |
| D3 | 96dpi | 144 | 画布 × 1.5000 | 405.30 → 406.30pt | ×1.0025 ✓ |

三组的呈现图都被替换成同一张（机器现场渲的），但**框都保持不变** ⇒ 公式里的机器项确实相消。

### 4. 判别边界

- **声明尺寸 = 对象框 ⇒ 必变大**（实测 7 个样本：声明=框的、1080p 那批、GDI+ 自产那批）；
- **声明尺寸 ≠ 对象框 ⇒ 正常**（实测 6 个以上样本，含声明比框小的情况）；
- 但"≠"只是必要条件：真正的约束是上面那条自洽式，声明偏离自洽值多少，框就按比例放大多少
  （例：参考设备写 96dpi 而声明按 120/188.5 算 ⇒ ×1.97；LogicalDpi 写 96 而声明没跟着改 ⇒ ×0.80）。

## 生成侧口径

1. **呈现图可以自己合成**，不必 Visio 渲染；也不必带画面（空白即可）。
   最小结构：`文件头 88 字节 + 第 1 条 EMF+ 头注释 44 字节`，共 **132 字节**。
2. **三个尺寸字段必须自洽**：`声明 = 画布 × (LogicalDpi ÷ 参考dpi)`。
   出图分辨率可任意假定（96/144/任意），只要这条成立。
3. **必须保留**：`rclFrame`、`nHandles = 3`、`szlDevice`/`szlMillimeters`、`LogicalDpi`、第 1 条 EMF+ 头记录（`0x4001`）。
4. **不要**：把声明尺寸写成对象框尺寸；用 `docProps/thumbnail.emf` 当呈现图；在既有渲染件上手工改 dpi 字段（会破坏自洽）。
5. **vsdx 侧建议**：剥掉 `docProps/thumbnail.emf`（连同其关系与内容类型）、把 `DrawingSizeType` 置 1。
   这两项在单变量实验里都不是开关，但它们是"与 Visio 保存过的图纸一致"的形态，保留不影响正确性。

## 我们这边（消费侧）

1. 嵌入时**自己合成 132 字节呈现图**：声明 = 画布 × (LogicalDpi ÷ 参考dpi)，
   参考设备与 `LogicalDpi` 取一组自洽值即可（本机实测可用 2560×1600px/345×215mm + 120，也可用 1920×1080/508×286 + 96）；
2. **写入前加护栏**：断言"声明尺寸 ≠ 对象框尺寸"（相等必出问题）；
3. 不再读 `docProps/thumbnail.emf` 当呈现图；
4. 不依赖 Visio：消费端不做现场渲染。

## 自检

1. **结构**：解析 `word/media/*.emf`，应为 88 字节头 + 44 字节 EMF+ 注释（或至少含完整头与第 1 条 `0x4001` 注释）；
2. **自洽**：`rclFrame ÷ 2540 ÷ 画布in ≈ LogicalDpi ÷ 参考dpi`（误差 < 1%）；
3. **不相撞**：声明尺寸与 `<v:shape>` 的宽高**不相等**；
4. **人工验收**（脚本判不了）：双击对象 → 关闭 Visio → 保存 → 重开，量 `<v:shape style="…">`；
   合格件会有 ≤0.5% 的抖动（实测 405.30 → 406.30pt），**变成画布尺寸或几十上百英寸就是不达标**。

## 未证与风险

1. **机制本身没有证明**：上面是从 13 个单变量样本拟合出来并跨 dpi 验证的**经验规律**，不是从 Word/Visio 内部逻辑推出来的；
2. 样本都在同一台机器、同一个 Word 版本上取得；跨 Word 版本、跨 Office 位数未验；
3. `L_r`（本机逻辑 dpi＝120）与 `P_r`（本机物理 dpi＝188.5）是这台机器的实测值；
   公式里它们会相消，但"相消"这一结论只在 D1–D3 三组上验过；
4. 替换图声明 = `画布 × L_r/P_r` 这一条由两张图纸（9.8599→6.2898、12.0523→7.6933）吻合到 0.3% 得出，未做更多图纸验证；
5. 未验：把 vsdx 的内嵌方式从 CFB 换成"原始 vsdx 部件 + package 关系"后，上述结论是否同样成立；
6. 未验：`DrawingSizeType` 与"剥缩略图"两项对最终形态的实际收益（单变量实验里都没有翻转结果）。
