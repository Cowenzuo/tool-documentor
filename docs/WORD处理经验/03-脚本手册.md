# 脚本手册

> 本页登记脚本与用法，分两类：**入库的**在 `scripts/`，**只在本机用的**在 `localscripts/`。
> 一次性的开发期草稿另放 `temp/`。

## 1. 本机的脚本（localscripts/，不入库）

`localscripts/` 整个目录被 `.gitignore` 忽略，clone 下来没有它，也不接受提交。
四类东西都放这里：

| 目录 | 放什么 | 入口 |
| --- | --- | --- |
| `localscripts/tests/` | 四个库包（core / templates / docx / postprocess）的单测 | `pnpm test:local` |
| `localscripts/e2e/` | E2E 冒烟探针：起真实 Electron 跑一遍打开工程到导出的主流程，含真实鼠标点击与真实方向键；渲染层出现 CSP 违规即判失败，焦点没进容器这类问题只有真事件才照得出来 | `pnpm e2e:local`（先构建再冒烟） |
| `localscripts/word-checks/` | Word 回读与读包核对脚本，见 1.1 | 见 1.1 |
| `localscripts/tools/` | 开发工具：CLI 导出对照与造样例工程，见 1.2 | 见 1.2 |

### 1.1 Word 核对脚本（localscripts/word-checks/）

前四个是 Word 回读，需本机装 Word；最后一个直接读包，不需要 Word。
命令都在仓库根执行。

| 脚本 | 用途 | 用法 |
| --- | --- | --- |
| `word-typography.ps1` | 逐样式回读字号、行距、段前后、缩进、对齐与中西文字体 | `-Path 出.docx` |
| `word-captions.ps1` | 标题编号、题注域、域更新前后对比、错误域统计 | `-Path 出.docx` |
| `word-tables.ps1` | 表格行列与纵向合并的跨行分布 | `-Path 出.docx [-Index 1]` |
| `word-images.ps1` | 内嵌图形数、图形尺寸、图片段落样式与对齐 | `-Path 出.docx` |
| `docx-check.cjs` | 不开 Word 读包：媒体、关系、域、合并、题注样式分布 | `node … <出.docx>` |

调用示例：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File localscripts\word-checks\word-images.ps1 -Path temp\export\out.docx
```

```bash
node localscripts/word-checks/docx-check.cjs temp/export/out.docx
```

写新脚本时的两条要求：`.ps1` 含中文必须存 UTF-8 带 BOM；`.cjs` 用 `findRepoRoot`
从脚本位置往上找仓库根，不要写死相对层数。

### 1.2 开发工具（localscripts/tools/）

| 工具 | 用途 | 用法（仓库根执行） |
| --- | --- | --- |
| `test-export.cjs` | 无界面的 CLI 导出对照：按实例 JSON 走 core → templates → docx 全管线出一份 docx，可选 OLE 嵌入 | `node localscripts/tools/test-export.cjs <instance.json> [出.docx] --templates <模板目录> [--embed-visio]` |
| `gen-sample-project.cjs` | 造合成样例工程：重写仓库根的 `samples/sample-project`（dproj + db），供存储兼容回归 | `node --experimental-sqlite localscripts/tools/gen-sample-project.cjs` |

两个脚本都从 `packages/desktop/package.json` 起解析 `@documentor/*`（`localscripts/` 不在 pnpm
工作区图里），用的是库包的 `dist/` 产物，所以先构建库再跑：`pnpm build:libs`（或 `pnpm ensure:libs` 按需构建）。

## 2. 入库的辅助脚本（scripts/）

这四个随仓库走，一键启动、按需构建与门禁流程会用到：

| 脚本 | 用途 | 入口 |
| --- | --- | --- |
| `start-documentor.cjs` | 一键启动：缺省起发布版（`release/win-unpacked/Documentor.exe`，不构建、秒开），`--dev` 或仓库根的 `.dev-mode` 标记起开发版 | `node scripts/start-documentor.cjs [--dev]`，`start-documentor.cmd` 同效 |
| `ensure-libs.cjs` | 库包按需构建：四个库的源码没变就跳过；`--force` 无条件构建，`--mark` 只刷新指纹 | `pnpm ensure:libs`、`pnpm build:libs:mark`，开发版启动时自动跑 |
| `check-upstream.cjs` | 上游 mmd2vsdx 的契约锚定检查，接口漂移即红灯 | `pnpm verify` 的收尾一项（报告模式，不阻断）；发布前用 `pnpm verify:upstream` 走严格模式 |
| `verify-package.cjs` | 打包产物内容校验，确认必备项齐全、上游不入包 | `pnpm verify:package`，打包后也可 `node scripts/verify-package.cjs` |

E2E 冒烟不在这一档：它只在本机用，在 `localscripts/e2e/`，入口是 `pnpm e2e:local`。

## 3. 开发期脚本（temp/）

一次性的数据整理、批量导出、临时核对都放 `temp/`，不入库，可随时清空。
这类脚本的共同点是依赖当时的工程数据，留着也跑不起来。

规范核查类的脚本目前也在 `temp/`：提交信息核查、文档行文核查、代码注释核查、
用户可见文案核查。它们在多轮整理里反复用过，若要长期保留，先判断是不是只有本机在用：
只在本机用的挪进 `localscripts/`，确实要随仓库走的才挪进 `scripts/`，两种都在本节登记。

## 4. 历史整理

零散的工作期提交可以在定版前按大事件整合，让主干一笔提交对应一个完整事件。
这属于定版前动作，由用户发起；平时开发一篇一提交，不改写已有历史。

整理提交信息的做法：

1. 先把旧信息与各提交的树哈希导出一份留档，作为回退依据；
2. 用 `git filter-branch --msg-filter` 逐条改写信息，映射表写成脚本，命中不到的
   一条会原样保留并打印警告；
3. 改完比对树哈希：22 棵树逐一相同才说明只动了信息、没动代码；
4. 确认无误后清掉 `refs/original` 与 reflog，让旧提交不再可达；
5. 工作区若还有未提交的改动，先用 `git stash` 收起，整理完再 `stash pop`。

注意：`--msg-filter` 的执行目录不一定是仓库根，命令里要用脚本的绝对路径。
