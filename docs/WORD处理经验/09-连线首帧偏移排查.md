## 1. 先排除消费端（这一条成立）

`packages/postprocess` 对 vsdx 是**字节透明**的：只做剥缩略图、可选的页面尺寸修补（默认关）、写 OLE 容器。
实测：服务直出 vsdx 与写进 docx 的内嵌件，形状数 / Connects / 母版数 / 字节数逐项一致 ✓。

## 2.5 单图对照实验：生成态 vs Visio 手动修后（**决定性证据**）

做法（可复现）：取第 2 张「系统能力协作流程」单独嵌入成一份 docx（`temp/工具/建两图实例.cjs <工程> 2`），
复制两份 —— 一份留作参照，一份**人工双击进 Visio、随便修一条连线、保存**；
然后用 `temp/工具/汇总连线差异.cjs` 逐字段对比两份 docx 里的内嵌 vsdx。

结果（12 条连线**全部**被 Visio 改动，模式一致）：

| 项 | 生成态（我们） | Visio 修后 |
| --- | --- | --- |
| `ConFixedCode` | **6（12/12 条都有）** | **被删掉（12/12）** |
| `BeginX/BeginY/EndX/EndY` 的公式 | `_WALKGLUE(BegTrigger,EndTrigger,WalkPreference)` | 一部分变成 **`PAR(PNT(Sheet.<id>!Connections.X<k>, Sheet.<id>!Connections.Y<k>))`**（钉到具体连接点） |
| 端点坐标值 | 例：`#16 BeginX 2.76050833333` | `3.171966666664`（重算） |
| 几何行 | 例：3 行 | 2 行 或 4 行（走线按新锚点重算） |
| 节点形状 | `Angle=0 / FlipX=0 / FlipY=0` 显式写出 | 三个默认值被删（**无实质差异**） |

⇒ **"连线偏移"的真正来源是：我们写了 `ConFixedCode=6`（把走线钉死、不参与重路由）✗，
并且端点只靠 `_WALKGLUE` 自动寻路、没有钉到具体连接点 ✗** —— Visio 一保存就把这两件事都改掉，
于是"随便修一条连线，其他都跟着好"（它把所有连线统一重锚+重算走线）✓。

生成侧可验证的修法（待 mmd2vsdx 侧确认）：

1. **别写 `ConFixedCode=6`**（不冻结路由）；
2. 端点按目标形状的**具体连接点**写：`BeginX/BeginY/EndX/EndY = PAR(PNT(Sheet.<id>!Connections.X<k>, Sheet.<id>!Connections.Y<k>))`
   （`Connections.X<k>/Y<k>` 要与 `Connects` 的 `ToPart` 对应）；
3. 锚点定了之后，几何行按同一走线算法重出（行数会变，属正常）；
4. 自检判据：修完后用同一支工具对比"生成态 vs Visio 修后"，**差异应为 0 个形状**。

## 3. 判据更正（本文初版给的自检判据会误报）

- ✗ 不要用"页面里不得出现 `F="Inh"` 的 XForm cell" —— 官方样本与正常产物会**全部误报**；
- ✗ 不要用"连线必须显式写 `Angle`" —— 官方样本的连线全部缺 `Angle`；
- ✓ 改用真不变量：**XForm 类 cell 的 `V` 缓存必须存在，且等于其公式的求值结果**
  （转换侧 `da6c50a` 的几何自洽断言就是同一路子）。

## 4. 可选硬化：暂不做（留档）

把连线 XForm 类 cell 从 `F="Inh"` 换成与母版等价的显式公式、并显式写 `Angle=0`：
好处是"不解析继承的消费者也能摆对"，代价是**文本形态偏离官方样本**，且它要解决的行为
**尚未被证实存在**（金标准同样带 `Inh`）。⇒ 先复现出"重启后仍错位"再动；真要做，
必须过"渲染与金标准逐字节一致"这道闸。
