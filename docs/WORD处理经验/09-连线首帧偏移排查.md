# 09 - 连线"显示偏移"排查（结论已更正）

> **更正（2026-09-28，同一日）**：本文初版把"连线 XForm 未写实、`Angle` 靠母版继承、页面无 `<Section N="XForm">`"
> 判成根因 ✗ —— **已被证伪**。官方 14 份样本、Visio 金标准、以及转换侧那份已验证可用的 `test-origin` 参照，
> 三者在这三项上与我们的产物**逐项相同**：`<Section N="XForm">` 数量 0、连线 XForm 类 cell 带 `F="Inh"`、
> 连线缺 `Angle`。⇒ 这是**官方形态**，不是缺陷；按它改形态反而会偏离官方 ✗。
> 教训与 08 §2 同一条：**"与我预期不符"不等于"有问题"** —— 判据必须先对照官方/金标准。

## 1. 先排除消费端（这一条成立）

`packages/postprocess` 对 vsdx 是**字节透明**的：只做剥缩略图、可选的页面尺寸修补（默认关）、写 OLE 容器。
实测：服务直出 vsdx 与写进 docx 的内嵌件，形状数 / Connects / 母版数 / 字节数逐项一致 ✓。

## 2. 真正的原因：那次导出跑的是**旧 dist**

| 时间 | 事件 |
| --- | --- |
| 15:17:57 | `dist` 构建完成 |
| **15:18:54** | 转换侧提交 `da6c50a`（连线走线缓存与端点自洽） |
| 15:38 | 那次导出 —— 服务实例加载的是 **15:17:57 的 dist** ✗ ⇒ 修复没生效 |

证据（由转换侧逐份量 15:38 那份 docx 的 23 个内嵌件）：

| 特征 | 修复后应有 | 15:38 那份 |
| --- | --- | --- |
| 水平连线几何行随 `LocPinY` 平移 | `MoveTo X=0 Y=-0.1` ✓ | `MoveTo X=0 Y=0` ✗（7.20pt 偏移的来源） |
| 端点框外投影 | 0.00pt ✓ | 11/23 份 2.2~3.8pt ✗ |

**重跑后（重建 dist 16:53 → 重启服务 pid 50900 → 重出 `-连线对齐版`）**：
`connector-align.mjs` 对 23 个内嵌件全部 **几何端点偏差 0.00pt、最大轮廓偏差 0.00pt** ✓。

## 3. 判据更正（本文初版给的自检判据会误报）

- ✗ 不要用"页面里不得出现 `F="Inh"` 的 XForm cell" —— 官方样本与正常产物会**全部误报**；
- ✗ 不要用"连线必须显式写 `Angle`" —— 官方样本的连线全部缺 `Angle`；
- ✓ 改用真不变量：**XForm 类 cell 的 `V` 缓存必须存在，且等于其公式的求值结果**
  （转换侧 `da6c50a` 的几何自洽断言就是同一路子）。

## 4. 可选硬化：暂不做（留档）

把连线 XForm 类 cell 从 `F="Inh"` 换成与母版等价的显式公式、并显式写 `Angle=0`：
好处是"不解析继承的消费者也能摆对"，代价是**文本形态偏离官方样本**，且它要解决的行为
**尚未被证实存在**（金标准同样带 `Inh`）。⇒ 先复现出"重启后仍错位"再动；真要做，
必须过"渲染与金标准逐字节一致"这道闸。

## 5. 防再踩"旧 dist"

转换侧建议在 `GET /health` 增加**构建指纹**（`dist` 构建时间或源码哈希）—— 同意加 ✓。
本侧对应约定：**导出前先读 `/health` 记指纹**（连实例 pid / 启动时间一起记进导出报告），
这样"旧 dist / 旧实例"这类问题在自检里直接暴露，不必靠时间线猜。
